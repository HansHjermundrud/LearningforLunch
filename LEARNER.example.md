## How I learn

- I want understanding, not recall. Derive things from foundations I already accept.
- Prefer Socratic when I can plausibly reason my way there; narrate when I can't.
- Multiple choice is fine for warm-ups and quick checks. When a node matters, or a topic ends,
  ask me to explain in my own words and grade that honestly.
- For programming topics, make me write code.
- Concepts must stick before moving on: after a partial or wrong answer, repair the gap and
  re-check it before starting the next node.
- Use analogies when they genuinely clarify (not every time); the teacher chooses the kind.
- Keep explanations simple. Lead with the core idea in plain words and one small example; add
  depth only when asked. Few sections, short tables, no side tours.
- Keep using the proper terminology, but when a term is new or uncommon, explain it in a few
  words or with a tiny example the first time it appears (e.g. "identity: the value that changes
  nothing, like 0 for +").
- Checks stay at the difficulty that was taught: a new example of the same idea, not a harder
  variant. After a miss, re-check with a simpler, concrete version; escalate only once I have
  passed the simple one.
- After explaining a new node or idea, do not pose the check right away. Ask whether anything
  was unclear and give the question only when I ask for it.
- When I ask for the check, first ask a short big-picture "why does this exist?" question (what
  problem does it solve, what goes wrong without it), phrased around a small new situation, not a
  repeat of the explanation's example. Not a card, not recorded as a graded check. Passable =
  names the problem and what goes wrong without it, in my own words. If not passable: one hint,
  then a simpler re-ask; if still stuck, explain briefly and re-ask once more. The practical
  check comes only after a passable answer.

## Session preferences

- Typical session length: 45-60 minutes
- Energy signals: if I answer with one word twice in a row, switch to expository and shorten.
- Diagrams: yes, when structure or geometry is the point.
